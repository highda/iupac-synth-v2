# Molecular discovery, cache and ordinary presets

This extension is optional to use and starts only after V0. It surrounds [CHEMISTRY](CHEMISTRY.md); it introduces no DSP mode, generated-only control, second Patch or second preset system.

## Selected finite delivery

Ship a curated offline molecular collection with common names, useful synonyms, identifiers and identifying metadata. Use a reproducible bounded snapshot of **Wikidata structured records**, cross-checked through chemistry identifiers/structure evidence and the pinned RDKit backend. Ship no Wikipedia prose/images and no full Wikidata/PubChem database. The release has **no runtime online discovery provider**. Name/SMILES analysis and browser operation work offline with bundled resources; synth startup/play/edit/render and saved-state restore do not depend on the browser/helper at all.

The data set delivers 256 validated distinct structures, with at least 128 outside the mapping panels, covering simple organics, aromatic/heterocyclic compounds, amino acids/short peptides, carbohydrates, lipids/steroids, common natural products, salts/inorganic examples within supported chemistry, and common solvents/material ingredients. Categories are discovery metadata, never mapper branches. Include at least 100 entries with two useful names, and tests for name collisions, stereo/charge/form distinctions and conflicting external records. This bounded curation is deliberately broader than a fixture alias dictionary, not a completeness claim about chemical nomenclature. Target source/index payload ≤16 MiB; report measured size, rejected records and coverage. These are release data acceptance/resource budgets, not DSP or identity constants.

**Tier A snapshot (owner decision 2026-09-21 on #138, supersedes the 256-record figure and the 16 MiB target above).** The shipped snapshot is every backend-viable Wikidata structure with at least one Wikipedia sitelink: label plus all English aliases, ranked by sitelink count. The exact numbers are in `data/discovery/manifest-v2.json`. A structure comes from the isomeric SMILES (P2017) when the item has exactly one, otherwise from the canonical SMILES (P233), which never gains invented stereo. A recorded InChIKey (P235) is cross-checked in full against an isomeric structure, and on its connectivity block only against a canonical one. One record is kept per canonical structure, the most-linked item winning, and the rest are listed as rejected. The bound is 40,000 records. The index and records are tens of MiB, a deliberate, accepted size: the data is not executed, and cold start and V10 are unaffected. The browser shows **ranked keyset pages of 50** (`ORDER BY rank DESC, record_id`, continued by a `(rank, recordId)` cursor, never OFFSET), fetched off the coordinator worker as the list nears its end. Search stays explicit (Search button or Enter), so it needs no debounce. Tier B (all ~1.26 M structures) is excluded from the bundle. The category list above remains discovery metadata.

## Source and storage comparison

| Alternative | Assessment and selection |
| --- | --- |
| Wikidata structured subset | Selected for names/synonyms, QIDs, display names and cross-references. Structured data is [CC0](https://www.wikidata.org/wiki/Wikidata:Licensing). Preserve entity revision/source URLs and evidence, including corrections/removals. Chemical truth is not implied by Wikidata rank or label. |
| Wikipedia articles/infobox scraping | Not selected. Unstructured prose, template churn, and [attribution/share-alike terms](https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use) add maintenance without needed metadata. A user-openable source link is sufficient; no embedded encyclopedia. |
| Full public KG or chemical dump | Not selected. [Wikidata download formats](https://www.wikidata.org/wiki/Wikidata:Database_download) support reproducible data access, but a full changing knowledge graph far exceeds this instrument's bounded index. An explicit QID/revision selection and archived responses suffice. |
| PubChem subset/API | Useful structure/identifier cross-check and broader optional discovery candidate. [PUG REST](https://pubchem.ncbi.nlm.nih.gov/docs/pug-rest) supports identifiers/synonyms and limits clients to five requests/second; contributor provenance requires review. Use recorded identifying facts/evidence during curation, not bulk copied descriptions or blanket licensing assumptions. No runtime adapter in this release. |
| ChEMBL/QM9/ZINC-style corpora | Not selected. ChEMBL's [downloaded database](https://chembl.gitbook.io/chembl-interface-documentation/downloads) includes bioactivity responsibilities we do not need; computational/screening sets are a poor common-name browser basis. No assay/property warehouse or dataset update service. |
| JSON/JSONL files + custom index | Keep versioned JSONL as portable source records. A hand-written searchable cache/index would own normalization, indexing and transactional updates unnecessarily. |
| SQLite | Selected for read-only snapshot index and separate writable discovery-cache metadata. Existing Python sqlite3 in private helper avoids new C++/ORM integration. SQLite provides [portable application files](https://www.sqlite.org/appfileformat.html). Use B-tree exact/prefix queries; deterministic ordering, escaped LIKE patterns and parameterized SQL. |
| SQLite FTS5 / separate search library | [FTS5](https://www.sqlite.org/fts5.html) is mature, but token relevance/fuzzy search is unnecessary for 256 entries and bounded cache. Do not implement custom fuzzy search either. Add neither FTS nor a search server. |
| One database for discovery and user presets | Reject. User sounds remain portable normal `.iupacpatch` files; discovery/cache deletion cannot delete or invalidate saved presets. |

Reproducible curation uses a checked-in finite QID manifest and archived, license-reviewed records identified by revision and SHA-256. Fetch/update is an explicit maintainer operation, separate from build/test. An adapter converts those records into the internal record schema, validates structures and emits sorted JSONL plus a deterministic logical SQLite index (byte-identical SQLite files are not required). No live service is needed to rebuild the index or run release gates. Record source archive, converter, backend and index schema versions; never invent missing revision/hash values. A source outage blocks refresh, not use of the existing snapshot. Ordinary releases replace the read-only snapshot as a unit; no background updater.

## Discovery record and canonical validation

A `DiscoveryRecord` schema 1 has a stable source-qualified record ID; provider/source ID and revision; common/preferred display names and aliases with language; optional systematic name, QID/CID/InChI/InChIKey; source structure text and format; retrieved timestamp, license and source URLs; validation status, backend/analysis version, exact canonical isomeric SMILES, and conflict/rejection diagnostics. No oscillator/module IDs or required generated patch. Bounds apply to records, strings/alias counts, results and total database size. Schema migration is confined to the external-data adapter/index rebuild.

Use [isomeric SMILES](https://www.wikidata.org/wiki/Property:P2017) or InChI/structure from a recorded primary compound reference where available. [Canonical SMILES](https://www.wikidata.org/wiki/Property:P233) alone must not invent stereochemistry. Parse/sanitize with the same production RDKit functions as direct input. Check supplied InChIKey against backend-derived identity where supported; compare archived reference structure under the same exact stereo/isotope/charge/fragment policy. InChI is cross-check metadata, not the deduplication key: it can normalize distinctions the product intentionally preserves. A parseable but contradictory record is not automatically validated.

Reject unsupported molecules and quarantine conflicting identifier/structure assertions; do not repair structures by silent desalting, neutralizing or removing stereo. General names such as “glucose” may describe multiple forms; expose the actual form/stereo in candidates, never label an unspecified structure D-glucose. A record without enough evidence remains non-applicable. Revalidation under a changed backend may alter its canonical result, so cached validation is versioned. No conversion to an IUPAC string is required before Analysis.

## Resolution precedence and ambiguity

1. **Explicit SMILES:** trim outer whitespace, preserve case/stereo, call canonical analysis directly. No alias lookup, heuristic name detection or network fallback.
2. **Explicit record selection:** resolve its source-qualified record/revision from the installed snapshot or cache, validate its exact structure with the current backend, display provenance/form, then Apply through the canonical analysis/projection/generator.
3. **Name input:** normalize Unicode punctuation and whitespace, case-fold for name matching only; preserve stereo qualifiers, locants and charge/form words. Query exact aliases across the installed snapshot and valid cache. Internal reviewed aliases are records in that same index, not a higher-priority hard-coded dictionary. Merge equivalent results by canonical structure plus backend identity version, retaining all source provenance. Source rank orders display only; it never hides a conflicting structure.
4. If exact results contain multiple distinct structures, show candidates and require selection. Do not fall through to OPSIN to silently resolve the collision. An exact single validated identity may resolve on explicit Name Apply; show what resolved and its provenance. A prior choice stays attached to that record, never becomes a silent global name override.
5. With no exact candidate, Name Apply attempts the local OPSIN parser. A successful result uses the same RDKit analysis; unsuccessful input leaves the patch intact. Browser prefix search may suggest candidates but never auto-applies a fuzzy/prefix result. Truncated result sets say so and require refinement; truncation cannot be interpreted as uniqueness.

Search/Browse returns candidates only. Selection reveals names, exact structure/identifiers, validation/source revision and conflict status. Apply explicitly generates an ordinary editable Patch and uses the established latest-generation transaction. Save as preset saves the current exact document through the ordinary synth action. Reopen cached generated content is an explicit load of a normal saved State with its original mapper version; “Generate with current mapping” is a separate labeled action. A separate preview engine is not required: MIDI audition after Apply uses the instrument itself.

## Persistence, cache and concurrency

| Domain | Contents / physical baseline | Lifecycle |
| --- | --- | --- |
| Discovery snapshot | Read-only SQLite index derived from versioned JSONL/archive; shipped in each full payload | Replaced atomically with application/data release; inspect source/version/hash. Old snapshot never required to restore a sound. |
| Discovery cache | Separate user-writable SQLite file: validated resolved records, query-to-candidate sets, provider/backend versions and timestamps | Disposable, clearable; startup never requires it. Current-version validated records can be used offline, with age/source displayed. Revalidate after backend/policy change; no automatic refresh network. |
| Generated base cache | Individual ordinary `.iupacpatch` State files, linked from cache metadata | Key includes exact canonical structure/analysis version, sonic/projection version, mapper version and explicit generation settings. Stored base/edited start equal, exact arrays/seed/macros included; cached State uses global defaults and generated macro defaults, never the requesting instance's live controls. Applying a cache hit takes its base Patch and retains live controls under normal Apply semantics; explicit cached-State load restores the stored controls. File content checked by shared codec. A hash is a file key/integrity check only, never an audible driver. |
| User presets | Normal `.iupacpatch` files in a user-selected/default preset directory, optional descriptive metadata | Save/load exact base/edited Patch and all controls using State v1; no eviction or implicit remapping. Filename supplies a display name when metadata is absent. Preset list scans these files; no separate browser preset format or mandatory database. |

Snapshot/cache SQL is owned by the chemistry helper using sqlite3, off audio and UI. The shell uses the same non-audio coordinator and bounded request/cancellation mechanism; there is no database thread in the synth engine or persistent service. Search is explicit (button/Enter); a local UI may filter an already returned page without spawning per keystroke. Multiple plugin instances may share a cache: use SQLite transactions/bounded busy timeout, per-file atomic replace and tolerate contention by bypassing cache. Never wait for cache from audio, and never fail an otherwise valid Apply merely because cache is read-only/full/corrupt.

Initial cache policy: at most 1000 metadata entries and 128 MiB total generated/cache storage, with least-recently-used eviction off audio; bounded diagnostics and filesystem cleanup. These limits and filenames are delegated resource policy with stress evidence. Eviction deletes only managed cache files, never preset directories. Cache clear explains that cached input/provenance is local user data. Negative lookup results expire with snapshot/backend revision (or a short bounded TTL); offline/errors do not become permanent absence. A cache schema mismatch rebuilds the disposable index or invalidates entries; never migrates user patches by rerunning chemistry. Crash/orphan cleanup is bounded and only touches cache-owned paths.

## Optional online policy and proof

There is no runtime online implementation or provider selector in this release. If concrete evidence shows the selected offline curation cannot meet this document's acceptance, the smallest repair may select a public provider through DECISIONS; inability to index the world's compounds is not such evidence.

Any approved adapter must be an explicit “Search online with <provider>” action showing destination and query, cancellable and deadline/response bounded; never send typed input per keystroke or transmit a whole preset/document. Use HTTPS, provider terms/provenance and rate limits, cache successful records, honor Retry-After and show failures/offline state while keeping local operation intact. For PubChem begin below its limit (at most one request/second per process, bounded retries); independent host processes must respect throttling responses, not promise a global cross-host quota. No live API is ever a release test dependency. Tests use recorded licensed responses and injected transport/time failures through the real adapter, if one is later approved.

[V11](VERIFICATION.md#required-automated-gates) proves common/synonym/prefix search, ambiguous/conflicting forms, stable offline records, canonical equivalence, cache version/eviction/concurrency/corruption behavior, Apply parity and exact preset restore after deleting all discovery/helper resources. Human BROWSE-01/02 evaluate candidate clarity, useful discovery and save/load workflow. Neither database row counts nor numeric audio distance proves musical usefulness.
