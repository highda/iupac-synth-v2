# Chemistry extension and patch generation

Built only on top of the [V0 synth-complete gate](VERIFICATION.md#required-automated-gates). This extension authors the same public Patch used by manual sound design; it does not define the engine's modules or instrument capability. Boundaries/state/UI: [ARCHITECTURE.md](ARCHITECTURE.md). Packaging: [TOOLCHAIN.md](TOOLCHAIN.md#self-contained-runtime-package).

## Analysis contract

Input resolution follows [DISCOVERY](DISCOVERY.md#resolution-precedence-and-ambiguity): explicit structure bypasses names; Name mode uses the shared local record index, resolves exact ambiguity visibly, then OPSIN 2.8.0 only when no exact local candidate exists. There is no parallel hard-coded name dictionary. SMILES mode preserves case, trims only outer whitespace, and never guesses names. Initial delegated resource policy: limit input to 4096 UTF-8 bytes without NUL/newlines. Require 1–256 heavy atoms, at most 8 disconnected components, and 512 total graph atoms. Reject queries, wildcard atoms, reactions and unsupported extended stereochemical input with a useful diagnostic.

Sanitize through RDKit, remove atom map annotations, remove ordinary explicit hydrogen spelling differences using RDKit's standard remove-H behavior, retain isotopes, formal charge and specified tetrahedral/double-bond stereo. Produce canonical isomeric SMILES; reparse it before structural ordering. Preserve all disconnected fragments. Do not neutralize, desalt, merge tautomers, invent unspecified stereochemistry or treat a racemate as a specified enantiomer. Equivalent atom/component spellings within the pinned backend must agree. Canonicalization can change with backend releases: version identity and save patches. See RDKit's [backward incompatible changes](https://github.com/rdkit/rdkit/blob/master/Docs/Book/BackwardsIncompatibleChanges.md).

Analysis contains: heavy atoms, molecular weight, formal charge, element counts (C/N/O/S/P/F/Cl/Br/I/other), aromatic atom fraction, ring count, fused ring adjacency count, rotatable bonds, fraction Csp3, HBD/HBA, TPSA, logP, carbonyl/amide/amine/alcohol/phenol/ether/aryl-halide motifs, and ordered structural details. Use RDKit's documented descriptor functions; motif SMARTS and unique-match counting definitions belong in a single versioned helper table. Ring metrics use the pinned RDKit ring set, not claims of a unique mathematical ring basis. Atom-local detail is the canonical traversal's tuple of atomic number, isotope, formal charge, aromatic flag, degree, bond orders, and assigned stereo label; retain the full bounded sequence, bond endpoint indices/order/stereo, and motif-match atom indices. Cap bonds at 1024 and total stored motif matches at 1024; enforce the response byte limit as well. This preserves actual connectivity and motif placement for local-detail reductions. Do not hash input text and call it canonical identity.

Helper request: `{protocolVersion:1, requestId, mode, text}`; response echoes requestId and has `status`, optional `analysis`, and bounded diagnostics. One request per process, JSON stdout only, diagnostics stderr capped at 64 KiB. Start the executable with an argument vector (never shell interpolation); use bounded request/response files in a private temporary directory if JUCE ChildProcess lacks stdin writing. Response ≤256 KiB. Wall deadline 45 seconds (OPSIN child 25 seconds), Java heap 256 MiB; raised from 15/10 under [D4](DECISIONS.md) on measured installed-closure evidence recorded by #42 — a freshly installed macOS payload costs 15.8 s on the frozen helper's first execution while the system validates the RDKit Mach-O closure and 7.9 s on the first OPSIN run, against 0.2 s and 5.3 s in steady state. Kill/reap the entire child tree on timeout/cancel/destruction; do not leave a nested Java child alive. At most one running job and one latest pending job per instance. Rapid edits only request work on explicit Apply, not per keystroke. Publish results only for the current request generation.

Unresolved, ambiguous or unsupported input leaves the audible patch intact and explains the failure or offers candidate selection. There is no text-hash fallback sound: the complete manual synth and saved/factory patches already provide useful operation. A missing/corrupt bundled helper reports repair/reinstall while ordinary synth playback remains available; that recovery does not pass installed molecular-input acceptance. Helper limits above are D4 resource policy, adjustable with measured supported-input/error evidence, not silent changes to identity semantics.

## Synth-independent sonic boundary

**Superseded in part by D13 (mapper 3, SonicIntent 2).** The intent is now the structural profile and the perceptual traits defined in [MAPPING-POLICY](MAPPING-POLICY.md); it still carries no module, parameter or edge vocabulary, and the generator still cannot reach back to Analysis, parse SMILES or consult a database. The seven-axis text below is the version-1 record.

SonicIntent v1 contains seven [0,1] musical axes: **density, brightness, rigidity, roughness, decay, harmonicity, motion**. It also carries explicit bounded ordered atom/bond/motif detail and the numeric structural summary required for local feature reductions, canonical identity and analysis/projection versions. It carries no source/filter/module/parameter IDs, synth values or edges. Projection knows no synth catalog; the generator cannot reach back to Analysis, parse SMILES or consult a database. Canonical identity is provenance/equivalence only, never a numeric sound driver.

This retains seven axes rather than restoring the legacy twenty-axis list. Density expresses compositional fullness, brightness spectral emphasis, rigidity regularity, roughness edge/noise tendency, decay temporal persistence, harmonicity pitched spectral alignment and motion temporal variation. Width, impulsiveness, periodicity and spectral complexity can be expressed by these axes plus ordered local structure without adding independent knobs or mandatory fields. The earlier `size/polarity/edge/sustain` names are replaced before implementation with musical `density/brightness/roughness/decay`. No saved SonicIntent migration exists or is needed.

Sufficiency is evaluated by P1 across broad, hard related families and holdout, including ordered peptide pairs. Seven scalars alone are not claimed to uniquely represent molecules; retained local topology/motif placement prevents count-identical structures from losing all available distinctions. Each projected axis has one or two salient feature drivers, with documented perceptual scaling/re-expansion and raw-to-scaled trace. Do not average a long correlated descriptor list into every dimension. Preserve isotope/stereo distinctions in analysis/detail without promising audible distinction for every stereoisomer.

## Deterministic patch composition

**Amended by D13.** Mapper 3 selects sources by a scored competition between voices, and a scalar may combine more than two traits; both were prohibited below and are now allowed by design. Everything else in this section still binds: one generator, explicit public Patch, a trace entry for every assignment, no hashes or fixture exceptions, byte-equivalent output for equivalent structure, no silent regeneration.

The sole generator returns a fully explicit public Patch plus ordered trace and exact mapping/projection versions/settings. It consumes musical intent and generic structural detail; all output validates/compiles through the manual synth path. Module selection, presence, serial/parallel edges, modulation source/destination/depth and scalars all respond to relevant features. No finite recipe selector, family-name branches, mandatory synthesis lanes, top-N/softmax lane competition or compulsory shared colour tail.

[Mapping policy](MAPPING-POLICY.md) defines the executable rules. They are versioned **mapping policy**, not permanent architecture: calibration may tune sparse transforms, topology conditions and source/processor composition inside the finite catalog and gates, without a new architectural approval for every threshold. Module/parameter/matrix semantics remain those of the public synth.

Each scalar uses at most two named axes plus a documented local structural reduction when needed; reductions must reveal the input atoms/bonds/motifs and arithmetic in trace. Every node/edge/row and parameter assignment records rule ID, feature inputs, pre-clamp and final values. Re-expansion must be tied to development data, not fixture names; report clipping and hard-family convergence. Source/branch gain compensation is measured through the production engine so loudness does not masquerade as identity. Canonical local placement, bond order and motif neighborhoods may affect harmonic/modal arrays and FM relationships. Hashes, cryptographic digests and pseudo-random skew may not replace this chemistry.

Equivalent canonical molecular structure with identical backend identity, projection/mapping versions and explicit settings yields byte-equivalent encoded base Patch regardless of input spelling, provider record, timestamp, cache state, UI controls or thread timing. Use stable generated role IDs independent of molecule text/hash; the explicit noise seed is a single documented fixed generation setting. User-authored DSP seeds remain ordinary Patch data. Do not use wall-clock RNG. Identity/content hashes are permitted for integrity/cache addressing only.

Saved generated base, edited Patch and controls restore directly; a backend/mapper upgrade cannot silently rerun generation. Explicit Reapply uses stored current-compatible Analysis, or clearly requests reanalysis of the stored exact structure when its schema/backend is unsupported. It reports the new versions and commits only on successful validation; otherwise keeps the last sound. No speculative old-analyzer compatibility layer is required. Stored base reset always remains possible without any helper.

## Mapper-coverage invariant

**Replaced by D13 (mapper 3).** "No catalog parameter may be dead for chemistry" is withdrawn: curated beats complete. `data/mapping-coverage.json` is generated from generation traces by `tools/build_mapping_coverage.py` and gives every catalog parameter exactly one entry with status `mapped` (a rule assigns it on the frozen panel; `mapping-calibration` fails if that rule stops firing), `offPanel` (assigned only for structures the panel does not contain) or `unmapped` (left at the catalog default, with a note). `mapping-coverage` checks the table against the live catalog, checks that drivers are SonicIntent-2 trait names, and keeps a floor of 60% of parameters reached. The text below is the mapper-2 record.

**No catalog parameter may be dead for chemistry.** Every parameter in the production module catalog whose `kind` is `continuous`, `discrete` or `convenience` must have exactly one entry in the coverage table `data/mapping-coverage.json`. `coefficientArray` parameters are covered through the convenience control or rule that authors them and carry an entry naming that authoring rule. The table is the contract surface; the mapper is the implementation of it.

Each entry declares `module`, `parameter`, `status`, `ruleId`, `drivers` and `note`:

- `status: "mapped"` — the production generator assigns this parameter from the listed drivers today. `ruleId` names the rule that appears in the generation trace.
- `status: "provisional"` — a driver is declared and the parameter is reachable, but the coefficient is explicitly uncalibrated. Introduced by D8 for the phase-4 additions; `note` names the pending work. Provisional is the labelled, allowed state — it is **not** an excuse to skip the entry. **The table carries no provisional entry any more**: #128 (W19) resolved all sixty-four phase-4 additions and the pre-existing `harmonic.partialPans` gap, so the status stays in the vocabulary for a future phase but a change can no longer land a parameter in it — `mapping-coverage` fails on any non-`mapped` entry.
- `drivers` must name at least one existing SonicIntent axis or `structuralDetail` field. **An empty `drivers` list is a failure, not a status.** Phase 4 adds no new analysis fields; widening the driver vocabulary from the full structural inventory is phase 5.

The invariant is enforced by the `mapping-coverage` test (`tools/test_mapping_coverage.py`), which reads the live catalog through the production `iupac-cli inspect --stage catalog` — not a transcribed copy — and fails when a catalog parameter has no entry, when an entry names a module or parameter that is not in the catalog, when a `drivers` list is empty, when a required field is missing, or when any entry is still `provisional`. Its other half lives in `mapping-calibration`, which is where the traces exist: that gate fails when a `ruleId` the table declares never appears in the generation trace over the frozen panels, so the table cannot keep claiming a rule the mapper has stopped firing. It runs in the chemistry-OFF build too, so a change that adds a parameter cannot land without declaring its mapping. Adding a parameter and its coverage entry in the same change is the intended workflow; a change that adds a parameter without one fails `ctest`.

Coverage is reachability, not quality. It proves no control is unreachable from molecular structure; it proves nothing about whether the correspondence is musical. V3/V4 remain the differentiation gates and a `provisional` entry must be resolved to `mapped` with calibration evidence before the release candidate.

## Integration and delivery

Expose input-resolution/Analysis/sonic/mapping inspection and generation in the existing CLI, and Apply/status/provenance in the existing native editor. Implement request cancellation/tree cleanup on the non-audio coordinator. A manual edit or load advances the document generation and invalidates a pending analysis request. Do not let packaged-helper work become a dependency of the earlier chemistry-disabled synth milestone.

Frozen and source helper must produce identical canonical Analysis for maintained inputs. Each delivered full product format contains its frozen Python/RDKit executable and private Java/OPSIN resources; test installed paths on a runtime-only machine/image. Preset playback with missing chemistry is useful recovery, not complete end-user delivery. The development container contains Java/Python for builds; this does not impose either runtime on end users.

Browser records are validated structures with metadata, never mandatory IUPAC strings. [DISCOVERY](DISCOVERY.md) owns source precedence, ambiguity, offline snapshot/cache and ordinary preset actions; those records enter this exact Analysis → SonicIntent → Patch implementation.
